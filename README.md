# GAPTECH speed governor certificate system

A small PHP + PostgreSQL web application. Staff enter the details once, and the system
issues a numbered certificate, prints it, produces a PDF, lets the client download their
own copy, and lets anyone verify a certificate online through the QR code.

The certificate sheet is an exact reproduction of the current paper sheet: compliance
certificate on the left, warranty card top right, office copy card and vehicle sticker
bottom right, on one A4 landscape page.

---

## 1. What you need on the server

* PHP 8.0 or newer, with the `pdo_pgsql` extension enabled
* PostgreSQL 12 or newer
* A web server (Apache via XAMPP on Windows, or Apache/Nginx on Linux)
* Optional: `wkhtmltopdf` for server-made PDFs. Without it the Print button still
  produces a PDF through the browser's own "Save as PDF".
* The fonts the certificate uses. On Windows they are already there (Calibri, Arial,
  Times New Roman). On Linux install them:
  `sudo apt install fonts-crosextra-carlito fonts-liberation fonts-dejavu`

No Composer packages and no internet access are needed. The QR codes are generated by
the application itself.

## 2. Install

1. Copy this folder onto the server, for example to `C:\xampp\htdocs\certificates`
   or `/var/www/certificates`.

2. Create the database and user:

   ```sql
   CREATE DATABASE gaptech_certs;
   CREATE USER gaptech WITH PASSWORD 'a-strong-password';
   GRANT ALL PRIVILEGES ON DATABASE gaptech_certs TO gaptech;
   ```

3. Create the tables:

   ```
   psql -U gaptech -d gaptech_certs -f sql/schema.sql
   ```

4. Edit `app/config.php`: database password, `base_url` (the address staff will type,
   e.g. `http://192.168.1.10/certificates/public`), and the path to `wkhtmltopdf`
   if you installed it.

5. Point the web server at the **`public`** folder, not the project root. Everything
   outside `public` must not be reachable from a browser.

6. Create your own account:

   ```
   php tools/create_user.php "Michelle" michelle@gaptechsolutions.com supervisor
   ```

7. Make `storage/` writable by the web server (on Linux:
   `sudo chown -R www-data:www-data storage`).

8. Sign in, open **Settings**, check the company details, and upload the authorised
   signature and company stamp images.

## 3. Before issuing real certificates

**Set the starting number.** In Settings, `Last certificate number used` must be the
highest number already used on paper. It ships as 13621. The system issues the next
number after it, so a digital certificate can never share a number with a printed one.

**Check the fonts and QR codes.** Open `tools/qr_selftest.php` in a browser and scan the
five codes with a phone. Each must open exactly the address printed under it. Delete the
file afterwards. Then issue one test certificate, print it, and scan the QR codes on the
paper itself.

**Decide the two open questions** with management: whether a digital certificate with an
embedded signature and stamp is acceptable to NTSA and KEBS, and whether a renewal
restarts the 12-month warranty.

## 4. Day-to-day use

**Issuing.** New certificate → fill the form → Save. Client, vehicle and governor records
are created the first time and reused afterwards, so a renewal only needs the dates. From
the dashboard's expiring list, "Renew" opens the form already filled in with that
vehicle's details.

**Printing.** The Print button opens the sheet and the browser's print dialogue. Set the
printer to A4, landscape, margins "None" and scale 100%. In the same dialogue, choosing
"Save as PDF" as the printer gives a PDF without wkhtmltopdf.

**Client downloads.** Client access → choose the client, set an e-mail and password, and
give the password to them by phone. They sign in at `client_login.php` and download any
of their certificates at any time.

**Verifying.** The QR code opens `verify.php`, which shows whether the certificate is
valid, expired or voided. Anyone can also look one up with the certificate number plus
the vehicle registration. No login needed.

**Mistakes.** A certificate is never deleted or edited. A supervisor voids it with a
reason, then issues a replacement. The voided one shows as voided on the verification
page, which is what protects you if a wrong certificate is already out there.

## 5. How it is put together

```
app/
  config.php        settings you edit
  bootstrap.php     database, sessions, helpers, login checks
  certificates.php  issuing, numbering, snapshots, PDF generation
  qr.php            QR code generator
  views/
    layout.php        page chrome
    sheet.php         the certificate sheet (A4 landscape)
    sheet_helpers.php drawing helpers used by the sheet
public/             the only folder the web server exposes
sql/schema.sql      database tables
storage/            generated PDFs (never served directly)
tools/              create_user.php, qr_selftest.php
```

Two details worth knowing if you change anything:

*Snapshots.* When a certificate is issued, every printed value is copied into
`certificates.snapshot`. The sheet is drawn from that snapshot, never from the live
records, so editing a client's name later does not alter certificates already issued.

*Sheet units.* The certificate layout uses the coordinates of the original sheet measured
at 200 dpi (2338 × 1653). A CSS zoom converts them to the printed page. Those numbers
were measured from the real certificate, so change them only against a printed sample.

## 6. First-run checklist

Work through this on the day you install it:

| Check | Expected |
|---|---|
| Sign in as staff | Dashboard opens |
| Issue a test certificate | Number is the next one after the setting |
| Open the sheet | All four parts appear, fonts look right |
| Print it | One A4 landscape page, nothing cut off |
| Scan both QR codes from the paper | Verification page opens, status Valid |
| Give a test client access and sign in as them | Only that client's certificates listed |
| Try downloading another client's certificate by changing the id in the address | Refused |
| Void the test certificate as supervisor | Verification page shows Voided |
| Check the audit log table | Rows for issue, print, verify and void |

## 7. Backups

The database holds everything that matters. Run a daily dump and keep a copy off the
office machine:

```
pg_dump -U gaptech gaptech_certs > backup-$(date +%F).sql
```

Back up `storage/` too if you use wkhtmltopdf, although any PDF can be regenerated from
its snapshot. Test a restore once, before you rely on it.

## 8. Known limits

* Written for a small office: two staff, one server, no queueing. Bulk issuing of many
  certificates at once would need a background job.
* Renewal reminders by e-mail or SMS are not included. The dashboard's 30-day expiry list
  is the manual version of that.
* Client passwords are set by staff, with no self-service reset.
* The certificate template hard-codes the layout of the current sheet. If the design
  changes, `app/views/sheet.php` changes with it.
